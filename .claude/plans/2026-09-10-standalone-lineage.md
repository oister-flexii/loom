## Selected policies

1. **Immediate advisory custody.** A tiny no-agent per-program publisher authenticates one completed review and publishes a complete immutable advisory disposition record with receipt. Parent triage remains autonomous under operator instructions; no new await-user stage. Accepted/deferred/dismissed and reasons are DECLARED policy, not adjudication or repair evidence. Exact duplicate publication is idempotent; conflicting bytes fail. Correction publishes a new record naming an exact previous revision of the same source, never an edit. Explicit forks are allowed; no inferred latest revision.
2. **Semantic resolution.** Every current issued reviewer must explicitly assess the same prior Finding as repaired against the same frozen successor snapshot and identify a relevant implementation change. Any still-present, not-assessable or missing assessment prevents resolution. A missing/malformed row refuses the whole response. Unanimity is reviewer judgment, not engine proof; Repair-Checked never implies resolution.
3. **Reopening.** An issued current reviewer may propose reopening with the exact prior origin and decision/refutation/resolution reference, full new evidence, the relevant changed implementation/dependency/contract/precondition or evidence contradicting the old reason, current applicability and evidence limits. No extra parent ballot. Critical re-adjudication uses a fresh bound full Refutation Panel and unchanged strict-majority rule. Preserve every old vote/reason. Parent prose cannot reopen/refute a critical. Reopening an advisory cannot promote its severity; policy reconsideration is recorded by a later parent disposition revision. Materially different assertions remain new Findings with an explicit relation, never a rewritten origin.
4. **Conservative successor scope/roster.** Reject before issuance if the successor drops predecessor review paths or reviewer roles; scope/roster may expand. Never silently broaden scope or reduce quorum. Roles/models/requests remain separate provenance. All current expected reviewers assess every inherited origin exactly once in deterministic order. Unavailable context yields an explicit not-assessable assessment, never closure. A current critical coverage limitation must not become a zero-critical install bypass.
5. **One predecessor.** Explicit authenticated source locator + Run/result identity; no run-name heuristics, automatic latest selection or multi-parent merging. Forks preserve separate origin identity. A bare `code-reviewer-1` is not cross-run identity.
6. **Historical policy.** Old missing policy is historical-decision-unavailable, not an empty native record or inferred decision. Permit explicit present-day import/attestation only with retained exact prose bytes/reference and DECLARED provenance; never backdate or infer IDs/decisions from prose. Missing/corrupt expected current publication fails, never falls back to historical absence.
7. **Relevant context.** Relevant dependencies/configuration/contracts must be included in explicitly selected frozen review scope; no mutable-live or implicit transitive-dependency context lane. Compare exact observed bytes/modes where available; unknown historical facts stay unknown. Git ancestry/HEAD equality is not semantic applicability or byte equality.
8. **Identity.** Preserve original Finding IDs/content/severity/location/basis and original published-result identity. New engine-attributed IDs continue per-role ordinal high-water across all inherited active/refuted/resolved/advisory histories. Current reviewer never mints IDs. Independent forks can share a local ordinal but not an origin. No text/path similarity merging.
9. **No digest cycle.** Current origins bind already-issued Run/request/transcript/ordinal, with enclosing publication supplying their eventual result identity. Inherited origins have known original publication references. Contexts bind the prepared lineage digest, not the final registration digest. Results never contain their own digest or a forward reference to future disposition records.
10. **Exact coverage.** Full prior inventory includes active, refuted, resolved and policy-retired rows. Current roster provides ordered, exact coverage with original references; unknown/duplicate/missing/reordered rows refuse atomically under existing attempt-1/2 policy. Infrastructure unavailability keeps the same semantic attempt. No synthetic product Finding on malformed payload. New vs inherited counts are distinct and engine-derived.
11. **Historical disposition retention.** Explicit current assessments may retain earlier disposition applicability, or propose reopening with evidence. A not-assessable critical history cannot authorize current closure/installation. Old decisions remain historical facts even when a new current assessment disagrees. Do not route already upheld unchanged active criticals through a new panel merely because a successor exists; only new criticals and explicit re-adjudication proposals need current panel work.
12. **P3 conservation.** Add a deliberate source-reader arm for the exact new result; retain full lineage and original IDs, use actual still-blocking critical IDs for accounting, never advisories/refuted/resolved rows. Preserve fixed operator checks, required fresh reports, bounds, candidate/index equality, guarded installation, v1 compatibility and normal exit requirements. Critical coverage limitations fail before installable authority; never strip lineage into a fabricated v2 result/digest.

## Discriminating acceptance criteria

- Two independent reviews reusing `code-reviewer-1` cannot be joined by bare ID; one chain preserves high-water across retired rows, branches stay separate.
- Advisory-only review with no remediation/successor still has authenticated immutable decisions; correction cannot rewrite old source/record; malformed/critical/duplicate/missing advisory entries reject.
- Historical missing policy and declared imports remain distinguishable from native publication; corrupted expected publication never becomes absence.
- Foreign predecessor/result/decision/request/context/transcript digest or wrong source scope fails at its actual production join, even with self-consistent attacker hashes.
- Whole-roster unanimity plus identified relevant change resolves on successor snapshot; one disagreement/not-assessable/omission prevents it. Repair-checked alone does not remove any obligation.
- Refuted/dismissed/resolved history remains exact; evidence-bound reopening reaches unchanged full panel where critical. New/distinct related Finding cannot replace original assertion or severity. Unchanged prior criticals do not restart adjudication.
- Prior rows appear exactly once in issued order, every current reviewer covers all; missing/duplicate/wrong-origin/oversized rows consume only existing semantic retry authority. No silent truncation or fabricated Finding.
- Same HEAD with changed bytes is a different successor source; different HEAD alone is no repair. Deleted/renamed files preserve origin location; missing historical context stays unknown. Narrowed scope/dropped roles fail preflight.
- New result bytes replay identically from native captured evidence without trusting result/checkpoint; P3 authenticates exact new result and conserves origin/current counts, including actual disposable guarded index installation.
- V1 and P4-v2 initial/resume/retry/result/receipt bytes stay exact; Wave remains v2 and unchanged. No source fixture relocation falsely treated as legitimate Run authority.
- All native tests own runtime, cwd, session ID/file and transport before import/spawn, restore environment, await child completion before cleanup. Never use actual parent bindings or global cleanup. Green assertions alone are not custody proof.
